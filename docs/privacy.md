# 隐私与媒体处理

## 信任边界

前端只负责预览和提交隐私矩形。所有公开发布的媒体必须由 Node.js API/Worker 使用服务端 Sharp 管线生成。客户端上传的“已模糊图片”仍会重新处理，不能直接进入公开桶。

## 处理步骤

1. API 校验用户、文件类型、大小和配额。
2. API 返回短期签名 URL，浏览器将原图上传到私有 `map-quarantine` 桶。
3. `/media/uploads/:id/complete` 校验对象确实存在且大小一致。
4. Worker 从隔离桶读取原图。
5. 如果启用 ClamAV，先执行 `INSTREAM` 恶意文件扫描。
6. Sharp 按 EXIF 方向旋转图片，并在重新编码时移除 EXIF/GPS 等元数据。
7. Worker 合并用户矩形和检测器返回的敏感区域。检测器超时、连接失败、5xx 或返回非法区域时，先在请求内做有限次退避重试；仍失败则**降级**：仅使用人工框选继续处理，并把媒体转入 `manual_review`，绝不让检测器这一依赖故障直接把媒体标记为 `failed`，也绝不跳过人工确认自动发布。
8. 服务端对区域进行安全边距扩展和模糊。
9. Worker 重新编码 WebP 并生成缩略图、SHA-256 和感知哈希。
10. 检测器健康时媒体才标记 `ready` 并复制到公开桶；未配置检测器或检测器降级时，处理结果停留在私有桶并标记 `manual_review`。
11. 审核员通过 10 分钟签名 URL 查看私有处理结果并确认隐私；也可以拒绝（退回上传者并通知，删除私有派生图）。
12. 只有确认后，处理图和缩略图才复制到公开桶并标记 `ready`。
13. 原图默认在 24 小时后由维护任务删除；失败或被拒绝的媒体最多保留 7 天。

## 异常恢复链路

处理管线把失败分成三类，统一走“降级 → 重试 → 通知 → 审核 → 发布门禁”的恢复链路：

| 失败类型 | 例子 | 处理 |
| --- | --- | --- |
| 瞬时故障（transient） | S3/ClamAV 连接抖动、公开桶复制失败、未知运行时错误 | 媒体保留在 `processing`，按指数退避重新入队（10s、20s、40s，上限 5 分钟）；Worker 崩溃时由看门狗恢复。`processing_attempts` 记录尝试次数，达到 `MEDIA_MAX_ATTEMPTS`（默认 3）后，若已有处理图则降级 `manual_review`，否则标记 `failed`。 |
| 检测器故障（detector） | 超时、连接拒绝、5xx、非法区域响应、400/4xx 拒绝 | 请求内重试 `PRIVACY_DETECTOR_RETRIES` 次（默认 3，退避基数 `PRIVACY_DETECTOR_RETRY_BASE_MS`）；仍不可用则只用人工框选产出图片并转 `manual_review`，通知上传者和全部审核员，写入审计日志。 |
| 永久故障（permanent） | 检出恶意软件、不支持的图片格式、超过像素上限、隔离原图丢失 | 立即 `failed`，清理公开桶残留对象，通知上传者，写入审计日志。用户可在投稿页或通过 `POST /media/:id/retry` 重试（重置尝试计数）。 |

- 入队时若 Redis/队列不可用，API 不再把媒体改成 `failed`：媒体留在 `processing` 并标记 `QUEUE_UNAVAILABLE_PENDING_RECOVERY`，Worker 维护任务会立即补入队。
- Worker 看门狗每分钟运行：先补入队“未入队”的行，再把扫描/处理阶段停留超过 `MEDIA_STUCK_MINUTES`（默认 20 分钟）的行重新入队；已用尽尝试次数的滞留行最终标记 `failed` 并通知，避免无限重试。
- 通知采用“站内信 + outbox 邮件”事务写入；通知本身失败只记录日志，不改变已经提交的隐私状态。
- 发布门禁不变：投稿允许 `ready`/`manual_review` 的媒体，但审核员批准地点前所有媒体必须为 `ready`；任何非 `ready` 媒体都不会返回公开 URL。

## 数据要求

- 原始文件对象键不可预测，隔离桶不允许匿名读取。
- 公开桶只允许已经过隐私确认的派生图。
- 日志中不得记录原图 URL、访问令牌、密码或完整个人信息。
- 默认不采集用户定位轨迹；浏览器定位必须由用户主动触发。
- 私人住宅内部、受限区域和实时人员位置不属于 V1 允许内容。
- 删除媒体时同时清理隔离原图、服务端处理图和公开派生图。
