# 隐私与媒体处理

## 信任边界

前端只负责预览和提交隐私矩形。所有公开发布的媒体必须由 Node.js API/Worker 使用服务端 Sharp 管线生成。客户端上传的“已模糊图片”仍会重新处理，不能直接进入公开桶。

## 处理步骤

1. API 校验用户、文件类型、大小和配额。
2. API 返回短期签名 URL，浏览器将原图上传到私有 `map-quarantine` 桶。
3. `/media/uploads/:id/complete` 校验对象确实存在且大小一致。
4. Worker 从隔离桶读取原图。
5. 如果启用 ClamAV，先执行 `INSTREAM` 恶意文件扫描。
6. Sharp 按 EXIF 方向旋转图片，并在重新编码时移除 EXIF/GPS 等元数据。
7. Worker 合并用户矩形和可选检测器返回的敏感区域。
8. 服务端对区域进行安全边距扩展和模糊。
9. Worker 重新编码 WebP 并生成缩略图、SHA-256 和感知哈希。
10. 没有自动检测器时，处理结果停留在私有桶并标记 `manual_review`。
11. 审核员通过 10 分钟签名 URL查看私有处理结果并确认隐私。
12. 只有确认后，处理图和缩略图才复制到公开桶并标记 `ready`。
13. 原图默认在 24 小时后由维护任务删除；失败媒体最多保留 7 天。

## 异常恢复链路

- **降级**：检测器已配置但超时、不可达或返回非法数据时，Worker 不会把媒体标记为失败，而是仅用人工框完成处理并转入 `manual_review`，隐私报告记录 `detectorDegraded` 与 `detectorError`。降级媒体绝不复制到公开桶，必须由审核员确认后才能 `ready`。
- **重试**：媒体处理任务自动重试 3 次（指数退避，30 秒起）；重试期间媒体保持 `processing`。重试耗尽才落 `failed`，上传者可通过 `POST /media/:id/retry` 再次处理，`failed` 与 `rejected` 状态均可重试。维护任务每 60 秒恢复卡住超过 20 分钟的 `scanning`/`processing` 媒体并重新入队。
- **通知**：处理最终失败、隐私复核通过或被拒绝时，上传者都会收到站内通知和邮件（事务性 outbox）。
- **审核**：`manual_review` 媒体进入审核队列，审核员可查看短期签名预览后确认（`privacy-approve`）或拒绝（`privacy-reject`，必须给出原因码）。拒绝后媒体标记 `rejected`，原图保留 7 天供排查。
- **发布门禁**：投稿提交时只允许引用 `ready` 或 `manual_review` 媒体；内容批准前再次校验所有引用媒体必须为 `ready`，任何降级、失败或被拒的媒体都无法绕过人工确认进入公开地图。

## 数据要求

- 原始文件对象键不可预测，隔离桶不允许匿名读取。
- 公开桶只允许已经过隐私确认的派生图。
- 日志中不得记录原图 URL、访问令牌、密码或完整个人信息。
- 默认不采集用户定位轨迹；浏览器定位必须由用户主动触发。
- 私人住宅内部、受限区域和实时人员位置不属于 V1 允许内容。
- 删除媒体时同时清理隔离原图、服务端处理图和公开派生图。
